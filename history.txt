벤치마크 결과 정확도와 지연시간이 너무 높아서 청킹 및 임베딩 문제일 가능성이 있기에

AI 질의했고 결과적으로는 임베딩 과정에서 title이 누락되는 현상을 발견.

```text
title(법령명)을 포함해서 재임베딩하는 스크립트를 만들겠습니다.
기존 recover_null_embeddings.py의 커넥션 풀/재시도/스레딩 구조를 그대로 재사용하되, 다음을 추가합니다:

전체 재임베딩 대상 (NULL만이 아니라 이미 임베딩된 행도 포함 — 지금 문제가 "content-only 임베딩"이므로 기존 값도 다시 만들어야 함)
재임베딩 전 안전장치: 임베딩 백업 테이블 자동 생성 (문제 생기면 롤백 가능)
--dry-run: API 호출 없이 title+content 결합 텍스트가 어떻게 만들어지는지 먼저 눈으로 확인
--limit / --doc-type / --where: 전체 실행 전에 소규모로 먼저 검증

1) Dry-run으로 결합 텍스트부터 확인 (API 호출 없음, DB도 안 건드림)

bash
python src/reembed_with_title.py --dry-run --doc-type law --dry-run-n 10

2) 소규모 실제 테스트 (문제가 됐던 그 법령으로 먼저)

bash
python src/reembed_with_title.py --where "doc_id = '010719'"

실행하면 먼저 legal_chunks_embedding_backup_YYYYMMDD_HHMMSS 테이블에 기존 임베딩을 백업한 뒤 재생성합니다.

3) 전체 실행

bash
python src/reembed_with_title.py --workers 4 --batch-size 20
원본 대비 바뀐 부분
build_embedding_text(title, content)가 핵심 변경점입니다 — "{title}\n{content}"로 결합해서 넘깁니다. 나중에 doc_type별로 포맷을 다르게 주고 싶으면 이 함수 하나만 건드리면 됩니다.
대상 조회를 WHERE embedding IS NULL이 아니라 전체 행(옵션으로 --doc-type/--where/--limit 필터) 기준으로 바꿨습니다 — 이미 content-only로 임베딩된 행도 다시 만들어야 하니까요.
재실행 전 자동 백업 테이블 생성을 넣었습니다. 재임베딩 결과가 오히려 더 나빠지는 경우(드물지만 발생 가능) 롤백할 수 있게요.

전체 재임베딩 끝나면 어제 history.csv에 남기던 것처럼 evaluate_retrieval_reranker_v2.py로 Q1(10·27법난) 케이스부터 다시 돌려서 law_010719_art_0001~0003이 이제 top-5에 들어오는지 확인해보시면 됩니다.
```
